# Update the code to use mise

I am recently switched to `mise` for managing the ruby versions. I think the `README.md` is not aligned with what is told in the `.tool-versions` (nor `.ruby-version`, or `.ruby-gemset`). I wonder if we can modernize the setup so that the repo will only need `mise` + `.tool-versions` instead.

## Plan

Tooling/docs change only — no domain/application/delivery layers involved. Ordered from the source of truth outward.

1. **Single source of truth for the Ruby version: `.tool-versions`**
   - keep `.tool-versions` (`ruby 3.4.3`) unchanged
   - in `Gemfile`, replace `ruby '3.4.3'` with `ruby file: ".tool-versions"` (supported by Bundler >= 2.5)
2. **Remove legacy version-manager files**
   - delete `.ruby-version` (redundant; ignored by mise by default)
   - delete `.ruby-gemset` (RVM-only; not used by mise)
3. **Rewrite `readme.md`**
   - requirements: [mise](https://mise.jdx.dev) (Ruby version pinned in `.tool-versions`)
   - setup: `mise install` then `bundle install` (drop `gem install bundler`, Bundler ships with Ruby 3.4)
   - run: `bundle exec jekyll serve --watch` → http://localhost:4000
4. **Verify**
   - `mise install`, `bundle install`, `bundle exec jekyll build` succeed
   - `Gemfile.lock` stays consistent

## Acceptance criteria

- the Ruby version is declared only in `.tool-versions`
- `.ruby-version` and `.ruby-gemset` no longer exist
- `readme.md` describes a mise-based setup that matches `.tool-versions`
- the site builds with `bundle exec jekyll build`

## Out of scope

- adding a `mise.toml` with tasks

## Progress

- [x] `Gemfile` reads the ruby version via `ruby file: '.tool-versions'`
- [x] removed `.ruby-version` and `.ruby-gemset`
- [x] `readme.md` rewritten for mise (`mise install` → `bundle install` → `bundle exec jekyll serve --watch`)
- [x] verified: `mise install`, `bundle install`, `jekyll build` and `jekyll serve` (HTTP 200) all succeed

Decisions:

- no test suite in this repo — each item was driven by a small shell check (Gemfile has no hardcoded version and bundler resolves the `.tool-versions` version; legacy files absent; readme describes mise and pins no version)
- added the generic `arm64-darwin` platform to `Gemfile.lock` (separate `chore` commit, not in the original plan) — without it every `bundle install` on Apple Silicon dirtied the lockfile; the OS-specific `arm64-darwin-27` was deliberately removed
- readme now uses `jekyll serve` (the canonical name) instead of the `server` alias
